# 09: IN/OUT交接与到期占用管理

## What to build

约定起日到达且物业人员确认 IN 后登记实际占用；交还时登记 OUT，记录照片与双方依据。合同约定租期到期与现场腾空相互独立：到期未 OUT 的单元仍不能交付下一家企业；正常 OUT 释放实际占用后单元才可重新交付。到期提醒可补发，重复扫描不重复生成待办。时间推进使用可控时钟测试，不实际等待。

本票只处理 IN/OUT 与实际占用、到期提醒。提前终止的费用截止与占用截止在 15 接入，同企业同单元无缝续租在 17 接入，本票不预先建立这些流程或伪造交接记录。

- IN 记录实际交接时间、经办人、依据与备注，登记后企业进入实际占用。
- OUT 记录交还时间、经办人、照片与双方依据，登记后释放实际占用。
- 实际占用与合同约定租期分别存储，到期扫描只生成提醒，不改占用事实。
- 交付检查同时读取实际占用与合同预订，未腾空时拒绝下一企业的交付。
- 到期提醒按合同与到期日生成业务键，补发与扫描都经过同一去重。
- IN/OUT 操作按园区角色鉴权，企业用户与范围外账号被拒绝。
- 交接历史保留，不被后续续租或终止覆盖。

## Acceptance criteria

- [ ] Migration 建立交接 IN/OUT 记录与照片、双方依据字段，空库迁移后可启动并使用真实 MySQL 验证。
- [ ] 约定起日到达前提交 IN 被拒绝；到达或之后确认 IN 后登记实际占用，记录时间与经办人。
- [ ] 合同约定租期到期本身不释放实际占用，未 OUT 时交付检查拒绝将单元交付下一家企业。
- [ ] OUT 记录照片与双方依据后释放实际占用，单元随后可被交付；交接历史可查询且不因后续操作删除。
- [ ] 到期提醒在到期前生成并可补发；模拟停机后补发仍能生成，重复扫描同一到期事实不产生重复待办。
- [ ] 到期与提醒使用可控时钟推进验证，不依赖真实等待。
- [ ] 物业人员只能在本园区范围执行 IN/OUT，企业用户或无权限账号的请求被拒绝。
- [ ] UI 可完成 IN 确认、OUT 登记与照片上传，操作结果持久化到 MySQL；越权账号看不到对应操作入口。
- [ ] 使用真实 MySQL 与真实认证上下文执行 HTTP/API 测试并保留原始输出，未执行的验证不写为通过。
