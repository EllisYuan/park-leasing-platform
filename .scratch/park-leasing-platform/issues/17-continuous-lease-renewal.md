# 17: 无缝续租与连续使用

Status: open
Label: ready-for-agent
Type: task
Blocked by: 09
Spec: [平台Spec](../spec.md)
User stories: 59, 60

## What to build

合同专员可为同企业、同出租单元的原合同创建次日衔接的续租新合同，经审批签署后在约定起日原子承接实际占用，不虚构交接。

- 续租创建关联原合同的新合同，保存新租期与面积、单价、费用条款快照；原合同租期与历史不被修改。
- 续租合同走正常审批签署；未签署前不得承接实际占用。
- 约定起日到达后，新合同以单一原子操作承接实际占用，来源标记为续租承接；不生成 IN/OUT 交接记录，资源查询不出现空置窗口。
- 仅同企业、同出租单元、次日衔接的续租成立；不同企业不走伪连续续租。
- 未签署或区间冲突的续租请求被拒绝；已存在有效关联续租时重复发起被拒绝。
- 押金转结不在本票，由票据 18 单独接入。

## Acceptance criteria

- [ ] 同企业同单元次日衔接的续租创建成功，新合同关联原合同并持久化条款快照。
- [ ] 未审批签署的续租合同不承接实际占用。
- [ ] 到达约定起日后承接实际占用，来源为续租承接，不产生 IN/OUT 记录。
- [ ] 承接前后资源查询不出现空置窗口，实际占用连续。
- [ ] 原合同租期与账单历史不变。
- [ ] 不同企业、非次日或区间冲突的续租请求被拒绝。
- [ ] 已存在有效关联续租时重复发起被拒绝。
- [ ] 续租承接在事务失败时实际占用与合同状态均不变，不出现中间态。
- [ ] 非合同专员或无权限账号创建续租被拒绝。
- [ ] UI 可创建并查看续租关联，Flyway migration 可在空库升级，真实验证保存请求、响应与查询输出。

## Context

本票对应 [平台Spec](../spec.md) Implementation Decisions 第 20 条与 User Stories 59—60。续租创建关联原合同的新合同而非修改租期；术语见 [GLOSSARY](../../../GLOSSARY.md)：实际占用、合同预订、租赁合同。

合同的审批签署依赖票据 09；实际占用承接不虚构 IN/OUT，依赖既有交接事实。押金转结在 18 单独接入，本票不处理资金。续租仍受整合同与完整出租单元边界约束，见 [ADR 0002](../../../docs/adr/0002-whole-unit-contract-boundary.md)；原子承接依赖单库事务，见 [ADR 0001](../../../docs/adr/0001-modular-monolith.md)。
