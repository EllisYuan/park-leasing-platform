# 14: 押金退款申请、复核与执行记录

Status: open
Label: ready-for-agent
Type: task
Blocked by: 12
Spec: [平台Spec](../spec.md)
User stories: 82, 90, 91

## What to build

财务可对押金来源发起退款申请，经异人复核后记录实际线下执行，形成押金来源的完整退款闭环。

- 财务针对押金来源提交退款申请，指定押金来源、退款金额与原因；申请时冻结相应待退保留额度，可用额度同步减少。
- 退款申请必须由不同人员复核；提交人与复核人相同被拒绝。驳回或撤销释放冻结额度，押金余额不变。
- 复核通过后由财务记录实际线下执行：金额、实际退款日期、方式、凭证与经办人；只有实际执行才减少押金余额。
- 允许分次退款，每次退款均有押金来源与对应批准记录；累计执行不得超过来源可用余额。
- 执行幂等：同一执行标识重复提交不重复扣减；并发执行不产生超退。
- 企业账号可在企业中心查看本企业实际退款记录及其凭证，附件按业务归属鉴权。
- 本票无真实自动打款，不接支付渠道，退款是线下资金事实的记录。
- 预收租金来源的退款不在本票，由票据 16 接入同一链路。

## Acceptance criteria

- [ ] 押金退款申请经 HTTP 提交后冻结额度，可用额度减少，DB 持久化来源与金额。
- [ ] 同一账号提交并复核被拒绝；异人复核可完成。
- [ ] 驳回或撤销后冻结额度释放，押金余额不变。
- [ ] 实际执行记录金额、日期、方式、凭证与经办人，执行后押金余额按金额减少。
- [ ] 重复提交同一执行标识不重复扣减；并发两笔执行不超退。
- [ ] 未复核的申请直接执行被拒绝。
- [ ] 分次退款的每次记录均可追溯到押金来源与批准，历史可查。
- [ ] 企业账号查看他企业退款被拒绝；私有凭证仅按业务归属鉴权下载。
- [ ] UI 可完成申请、复核与执行操作，Flyway migration 可在空库升级，真实验证保存请求、响应与查询输出。

## Context

本票对应 [平台Spec](../spec.md) Implementation Decisions 第 30 条与 User Stories 82、90—91，先完成押金来源的退款垂直闭环。术语见 [GLOSSARY](../../../GLOSSARY.md)：实际退款与审批通过不同，执行记录才代表资金事实。

来源与可用额度由票据 12 的押金台账提供；预收租金来源的退款不在本票，由 16 接入同一链路，因此本票不依赖 13。企业可见性与附件鉴权沿用 [ADR 0003](../../../docs/adr/0003-browser-session-authentication.md)，资金一致性依赖单库事务，见 [ADR 0001](../../../docs/adr/0001-modular-monolith.md)。无真实自动打款。

验证证据使用真实 MySQL 与真实认证上下文执行 HTTP 请求并保留原始输出，未执行的验证不写为通过。
