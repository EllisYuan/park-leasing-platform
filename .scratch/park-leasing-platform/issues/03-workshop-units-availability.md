# 03: 楼栋、出租单元与基础租控

Status: open
Label: ready-for-agent
Type: task
Blocked by: 02
Spec: [平台Spec](../spec.md)
User stories: 18, 19, 20, 21

## What to build

在园区下建立楼栋与完整出租单元台账，楼层作为单元属性，同一空间不能重复登记为多个出租单元；登记面积、厂房条件、指导价与底价，支持维修与停用状态维护。后台提供可操作的租控列表、详情与基础区间查询，按拟租区间、面积与厂房条件筛选单元。

本票只建立已实现的状态事实：维修与停用。意向暂占由 07 接入、合同预订由 08 接入、实际占用由 09 接入，各自补上相应票的可用性判断，不提前假装具备未实现的履约能力。查询以完整单元为单位，不做任意面积切割；已被业务引用的资产不物理删除，以状态维护保留追溯。

- 楼栋属于园区，出租单元属于楼栋；楼层作为单元属性，不单独建层级。
- 单元状态至少区分可用、维修与停用，并以状态而非删除维护生命周期。
- 指导价与底价按单元保存，供后续意向报价路径使用，本票不实现审批。
- 租控查询接受拟租起止日期、面积与厂房条件，结果按园区范围过滤。
- 单元列表与详情共用同一范围解析，避免入口差异造成越权。
- 迁移与真实 MySQL 集成测试环境在实现中锁定，测试可重复执行。

## Acceptance criteria

- [ ] Migration 建立楼栋与出租单元表，保存面积、楼层、厂房条件、指导价与底价，空库迁移后可启动并使用真实 MySQL 验证。
- [ ] 可创建园区下的楼栋与完整出租单元；与已有单元空间重叠的登记被拒绝，错误信息可定位冲突对象。
- [ ] 单元的面积、楼层、厂房条件、指导价与底价可维护并按园区范围查询，更新后查询结果与数据库一致。
- [ ] 维修与停用状态可登记；停用单元不出现在可用结果，维修单元保留可见并明确状态，不以删除代替停用。
- [ ] 按拟租区间、面积与厂房条件查询返回匹配单元；本票结果只依据已实现状态，不伪造未来合同预订、意向暂占或实际占用数据。
- [ ] 已被业务引用的单元尝试物理删除被拒绝，历史与引用关系保留。
- [ ] 园区 A 的资产管理员不能读取或修改园区 B 的楼栋与单元，越权请求返回拒绝且不泄露对象是否存在。
- [ ] UI 可完成楼栋与单元维护及租控筛选查询，操作结果持久化到 MySQL。
- [ ] 使用真实 MySQL 与真实认证上下文执行 HTTP/API 测试，原始输出保存为证据，未运行的验证不写为通过。
