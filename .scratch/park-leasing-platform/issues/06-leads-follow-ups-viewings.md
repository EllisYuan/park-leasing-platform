# 06: 招商线索、跟进与带看记录

Status: open
Label: ready-for-agent
Type: task
Blocked by: 03
Spec: [平台Spec](../spec.md)
User stories: 28, 29, 38

## What to build

结构化登记招商线索：来源、企业需求、负责人与所属园区。客户可以是尚未核验的企业或联系人，不强制以 04 开户作为前提。列表与详情按本人及部门范围访问，部门外不可见。跟进记录保留实际发生时间、内容、下一行动；实际带看作为独立事件登记到具体单元与时间，阶段历史只记录真实发生的事件，允许跳过阶段而不补造带看记录。

带看记录不同于 21 的预约，不创建预约时段也不产生任何租赁占用。跟进附件采用与 04 相同的私有文件契约的最小闭环：授权上传、绑定业务归属、鉴权下载、不可公开访问；不新建公开存储。04 完成后复用其文件服务，本票不以 04 为阻塞，也不另立第二套文件规则。

- 线索记录来源、需求描述、负责人、所属园区与当前阶段；客户信息可为未核验的临时名称与联系方式。
- 跟进记录实际发生时间（可补录历史时间）、内容、下一行动与经办人，按时间排序展示。
- 带看事件记录单元、开始时间、参与人员与结果，独立于预约与意向。
- 阶段历史记录阶段变化的时间与依据，允许跳过阶段，历史中不出现补造事件。
- 范围按本人与部门解析，部门外读取与写入都返回拒绝。
- 线索与跟进附件使用统一私有文件契约，上传、绑定与下载均鉴权。
- 列表与详情使用同一范围解析，导出等后续入口复用同一规则。

## Acceptance criteria

- [ ] Migration 建立线索、跟进、带看与阶段历史表，空库迁移后可启动并使用真实 MySQL 验证。
- [ ] 可创建来源、需求、负责人与园区完整的线索；未核验客户无需企业账号即可存在于线索中。
- [ ] 跟进内容、实际时间与下一行动持久化，列表按时间呈现；仅本人与部门范围可读写，部门外请求被拒绝。
- [ ] 带看事件登记具体单元与时间；无需先有预约记录即可登记，带看不改变单元可用性或占用状态。
- [ ] 阶段变更为后续阶段时，历史只新增真实发生的事件，不自动补造带看或转化记录。
- [ ] 跟进附件按私有文件契约上传并绑定，公开地址不可访问，未授权用户下载被拒绝。
- [ ] 园区 B 的招商人员不能读取或编辑园区 A 的线索、跟进与附件，拒绝响应不泄露对象是否存在。
- [ ] UI 可完成线索列表与详情、添加跟进与下一行动、查看阶段与带看历史，操作结果持久化到 MySQL。
- [ ] 使用真实 MySQL 与真实认证上下文执行 HTTP/API 测试并保留原始输出，未执行的验证不写为通过。
