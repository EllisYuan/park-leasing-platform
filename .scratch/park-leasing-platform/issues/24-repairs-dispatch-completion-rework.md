# 24: 报修、派单、完工与返工

Status: open

## What to build

企业用户对实际有权使用的单元提交带照片的报修；物业受理、派单、处理、完工均保留时间与人员；完工通知后企业可确认关闭或申请返工；完工并通知起 48 小时无反馈可超时关闭，标明原因且明确非企业验收、不评分，之后仍可申请返工并保留原历史。站内待办与未读提示定时刷新；紧急情况显示线下联系电话。企业端手机宽度可用。

报修授权以实际占用中的单元为依据，不以合同或意向状态本身代替；同一工单的全部轮次共享一条主记录但各自保留处理历史，关闭与超时关闭都不删除或改写既有轨迹。

## Acceptance criteria

- [ ] 企业用户仅能对本企业实际占用（有权使用）的单元提交报修并附照片，无权单元被拒绝；照片按既有私有文件契约保存并按业务归属鉴权下载。
- [ ] 工单受理、派单、处理、完工各步记录人员与时间；仅被分配的处理人员可执行处理操作，越权返回 403。
- [ ] 企业确认完工关闭或申请返工；返工建立新的处理轮次并保留原轨迹不覆盖；工单明确标注非企业验收、不评分。
- [ ] 完工并生成站内通知起 48 小时无反馈可标记超时关闭（以可控时钟推进验证），记录原因；超时关闭后企业仍可申请返工。
- [ ] 站内待办与未读提示定时刷新且企业可见；紧急场景显示线下联系电话，不依赖普通工单应急。
- [ ] 权限边界：跨企业、跨园区工单的列表、详情与附件访问被拒绝，各入口一致鉴权。
- [ ] 企业端手机宽度可完成报修、查看进度与确认/返工；数据落库。
- [ ] 必要 migration（工单、状态与处理历史、通知/待办）可空库执行并保留既有数据。
- [ ] 证据：真实 HTTP 与 MySQL 输出及完整状态轨迹；未执行项如实标注。
