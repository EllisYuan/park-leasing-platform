# 07: 报价审批与7天意向暂占

Status: open
Label: ready-for-agent
Type: task
Blocked by: 05, 06
Spec: [平台Spec](../spec.md)
User stories: 40, 41, 42, 43, 44, 45, 47

## What to build

招商专员为一个出租单元提交招商意向，记录拟租区间与报价，按指导价/底价确定审批路径：报价不低于指导价走业务校验；指导价以下且不低于底价经招商经理；低于底价经招商经理与园区负责人并说明理由。审批通过即按拟租区间暂占该单元 7 天，界面与站内待办显示期限；首版一个单元最多一张有效意向暂占。

撤回、驳回或过期只释放本单，不影响后来接管资源的合同；并发意向冲突时只有一方成功；过期意向必须重新校验可用性与报价并重新审批。到期扫描使用可控时钟测试，重复执行幂等，不误释放已由合同接管的占用，该接管场景在 08 验证。

- 意向记录单元、拟租起止日期、报价与申请人；一意向只对应一个单元。
- 审批路径由报价与单元指导价、底价比较决定，比较在服务端取当前单元价格快照。
- 暂占从审批通过时刻起算 7 天，记录单元、区间与来源意向，过期状态可查询。
- 到期扫描按暂占记录处理，只处理属于本意向且未被接管的记录。
- 并发控制以数据库约束与锁保证，不依赖先查后写。
- 审批人待办与期限展示由 05 的待办服务承接。
- 过期后的原意向保留历史，重新提交形成新的校验与审批记录。

## Acceptance criteria

- [ ] Migration 建立意向、暂占、审批记录与待办关联表，空库迁移后可启动并使用真实 MySQL 验证。
- [ ] 三条报价路径可分别触发并分支正确：不低于指导价业务校验通过，指导价以下且不低于底价经经理，低于底价经经理与负责人且理由必填。
- [ ] 审批通过的意向按拟租区间产生 7 天暂占，期限在 UI 与待办中可见；可控时钟推进到期后暂占失效并要求重新校验审批。
- [ ] 相同单元冲突区间的两个并发意向只有一方取得有效暂占，另一方收到可理解的冲突失败（真实 MySQL 并发验证）。
- [ ] 首版一个单元最多一张有效意向暂占，已有有效暂占时新意向被拒绝而不产生第二条有效记录。
- [ ] 撤回、驳回或过期只释放本单暂占；重复执行到期扫描不重复释放、不误释放其他记录。
- [ ] 意向重新审批后，旧到期扫描重放不得释放尚未到期的新暂占；合同接管后的误释放回归由 08 验收，不作为本票完成前置。
- [ ] 审批人待办随提交、通过与驳回更新状态，期限展示持久化。
- [ ] 无园区角色或非当前园区范围的用户不能提交或审批意向，越权请求被拒绝。
- [ ] 使用真实 MySQL 与真实认证上下文执行 HTTP/API 测试并保留原始输出，未执行的验证不写为通过。
