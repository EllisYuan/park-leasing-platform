# 13: 账单作废重开与关联调整

Status: open
Label: ready-for-agent
Type: task
Blocked by: 11
Spec: [平台Spec](../spec.md)
User stories: 75

## What to build

财务可对未收账单经审批作废重开，对已发布费用以关联调整更正差额，历史版本与原因可追溯。

- 未收（无任何收款）的应收账单可发起作废，经审批后重开：原账单保留，新账单与原账单关联并记录原因。
- 已发布且已有收款或已有后续依赖的费用不得原地改金额或删除历史；差额一律通过账单调整处理，调整明细关联原账单。
- 调整差额分为正差与负差：正差形成待收明细；负差先冲减原账单未收部分，冲减后仍有超额的，形成有来源的预收应退记录，与押金分列。实际退款由票据 16 接入，本票不执行退款。
- 每次调整幂等，重复提交不重复生成；UI 可对照调整前后金额、差额构成与原因。
- 操作权限服务端校验，无财务权限或越权访问他企业账单被拒绝。
- 本票不引入收款红冲，也不以红冲或退款记录冒充账单调整。
- 通知按既有站内待办能力异步触发，不新增外部通道。

## Acceptance criteria

- [ ] 未收账单经审批作废后重开，原账单保留并与新账单关联，作废原因持久化。
- [ ] 已有收款的账单作废请求被拒绝；金额变更只能以关联调整产生。
- [ ] 正差调整生成待收明细并计入账单余额；负差先冲减原账单未收部分。
- [ ] 负差超过未收部分时形成有来源的预收应退记录，且不产生实际退款或收款红冲。
- [ ] 同一调整请求重复提交不重复生成调整记录。
- [ ] 作废重开的新账单保留原账单费用期间与单元明细来源，前后可追溯。
- [ ] 作废或调整操作在事务失败时，原账单与历史调整不出现半成品状态。
- [ ] UI 可对照调整前后金额、差额与原因。
- [ ] 无财务权限账号调用作废或调整被拒绝；他企业账单不可见。
- [ ] 历史账单版本与关联可在 DB 中查询，Flyway migration 可在空库升级，真实验证证据保存。

## Context

本票对应 [平台Spec](../spec.md) Implementation Decisions 第 26 条后半段与 User Stories 75。账单调整与应收账单术语见 [GLOSSARY](../../../GLOSSARY.md)，调整不是收款红冲，也不等于实际退款。

已收费用差额关联调整依赖票据 10 的账单明细与票据 11 的收款事实；预收应退仅形成有来源记录，实际退款在 16 接入 14 的退款链。模块边界与事务一致性见 [ADR 0001](../../../docs/adr/0001-modular-monolith.md)，合同不可部分退租的边界见 [ADR 0002](../../../docs/adr/0002-whole-unit-contract-boundary.md)。

验证证据使用真实 MySQL 与真实认证上下文执行 HTTP 请求并保留原始输出，未执行的验证不写为通过。
