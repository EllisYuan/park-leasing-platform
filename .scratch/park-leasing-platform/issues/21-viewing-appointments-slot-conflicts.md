# 21: 看房申请、确认与时段互斥

Status: open
Label: ready-for-agent
Type: task
Blocked by: 20
Spec: [平台Spec](../spec.md)
User stories: 33, 34, 35, 36, 37

## What to build

访客在门户对房源申请未来 14 天内的 30 分钟看房时段（09:00—12:00、14:00—18:00，可配置），招商回访后确认并安排带看人员。确认的预约同时占用“房源 × 时段”和“带看人员 × 时段”，两者都不得重复。支持取消与改约，历史保留。预约只是看房安排，不取得租赁占房权；意向暂占或合同预订期间仍可安排看房，但不承诺冲突租期。匿名访客不能查询内部安排与处理进度。前台与后台关键操作在手机宽度可用。

预约记录不改变房源的租赁占用状态，只维护预约自身的房源与人员时段占用；可约时段窗口由运营配置，配置变更只影响新申请。

## Acceptance criteria

- [ ] 访客在房源详情页选择未来 14 天内的 30 分钟可约时段提交申请，申请持久化到 MySQL；可约窗口与午休排除可配置，窗口外时段不可选或被拒绝。
- [ ] 招商人员回访后确认预约并指定带看人员；确认后房源与该人员对应时段写入占用约束（唯一约束或条件更新），状态历史可追踪。
- [ ] 并发验证：两个请求同时确认同一房源同一时段、或同一带看人员同一时段，只有一个成功，另一个返回冲突业务错误；在真实 MySQL 上验证约束与事务回滚。
- [ ] 取消释放房源与人员时段并保留申请/取消历史；改约到冲突时段被拒绝，改约成功释放原时段。
- [ ] 预约不产生租赁占用：预约与意向暂占、合同预订、实际占用分开存储，预约既不阻止也无法承诺冲突租期；暂占期内可安排看房。
- [ ] 权限边界：匿名访客不能查询、修改或取消内部安排，不暴露内部处理进度；后台确认、派带看与取消需招商权限并受园区数据范围约束。
- [ ] 门户申请与后台安排、带看人员在手机宽度可完成以上流程；数据落库。
- [ ] 必要 migration（预约、时段、人员占用与历史）可空库执行并保留既有数据。
- [ ] 证据：真实 HTTP 与 MySQL 输出，覆盖并发冲突、时段边界与窗口外拒绝；未执行项如实标注。
