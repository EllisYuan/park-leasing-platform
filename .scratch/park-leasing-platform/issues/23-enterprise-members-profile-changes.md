# 23: 企业成员与资料变更审核

Status: open
Label: ready-for-agent
Type: task
Blocked by: 04
Spec: [平台Spec](../spec.md)
User stories: 13, 14, 15

## What to build

企业管理员在所属企业内创建受限成员并配置企业内权限；普通成员默认只能进行基本查询与报修，敏感合同、资金与成员管理不默认开放。企业资料变更由企业管理员提交，运营核验通过后生效，旧资料与审核依据可追踪。账号始终归属一家企业；权限变化使相关会话失效或重新鉴权。企业端在手机宽度可用。

企业内权限逐项授予，拒绝默认开放；成员管理本身也是被授权能力，未获授权者不能查看成员列表或代他人操作。资料变更申请不直接覆盖当前资料，核验通过后才形成新版本。

## Acceptance criteria

- [ ] 企业管理员创建成员并配置企业内权限（如合同、资金、成员管理）；普通成员默认仅基本查询与报修，敏感合同、资金与成员管理默认不可见。
- [ ] 企业管理员提交本企业资料变更申请，运营核验通过后生效；申请前后值、审核人、时间与依据持久化可追踪，未通过时不改当前资料。
- [ ] 权限被撤销或调整后相关会话失效或下次请求重新鉴权；账号不能切换所属企业。
- [ ] 权限边界：修改企业、成员或资源 ID 访问其他企业数据被拒绝（403/404）；成员列表、详情与操作执行一致鉴权。
- [ ] 受限成员登录后只能访问被授予的企业中心功能；企业端手机宽度可完成成员管理与资料申请，数据落库。
- [ ] 与 24 的衔接：24 先按企业管理员交付报修入口；本票完成后回归验证普通成员报修受本票权限模型约束。
- [ ] 必要 migration（成员、企业内权限、资料变更申请与审核历史）可空库执行并保留既有数据。
- [ ] 证据：真实 HTTP 与 MySQL 输出，覆盖跨企业拒绝与会话重新鉴权；未执行项如实标注。
