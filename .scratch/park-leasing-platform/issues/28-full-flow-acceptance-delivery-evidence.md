# 28: 全链路验收与交付证据

Status: open
Label: ready-for-agent
Type: task
Blocked by: 21, 22, 23, 24, 26, 27
Spec: [平台Spec](../spec.md)
User stories: 110

## What to build

在最终集成版本回归完整交付链路：招商到收款、续租与退租资金链、跨企业与跨园区的附件和导出权限、门户与企业端手机关键路径，以及数据库与附件的完整备份恢复。补齐明确标注虚构的演示种子数据、截图来源与运行说明、原始输入输出与真实性能测量环境。各票应已完成自身测试，本票不补一切测试；不得存在未解释失败，失败或未执行如实报告，不伪通过，不修改原始论文 Word。

演示数据与真实业务数据分开标识；验收记录以可追溯的运行输出为准，人工算例只作预期对照，不作为应用已运行的证据。

## Acceptance criteria

- [ ] 最终集成版本跑通招商、合同、首期分段账单到部分收款主链，断言响应、状态与资金明细持久化（真实 HTTP/MySQL）。
- [ ] 跑通续租与退租资金链：押金转结成对记录、终止结算、预付应退与押金分开、实际退款以线下凭证记录且不重复执行（非自动打款）。
- [ ] 跨企业、跨园区权限回归覆盖列表、详情、统计、附件与导出，一致拒绝越权；附件按业务归属下载。
- [ ] 门户与企业端关键手机路径经浏览器流程验证可用。
- [ ] 最终 tip 重跑数据库与附件完整备份恢复至独立环境并核对关联，与 27 的早期验证并存且不矛盾。
- [ ] 提供明确标注“虚构”的演示种子数据及来源说明；截图注明来源与运行方式；验证记录保留原始输入输出。
- [ ] 性能测量记录真实环境、数据量、并发与原始输出，不预填结论。
- [ ] 交付清单完整可复现，无未解释失败；失败与未执行项如实列出；不修改原始论文 Word/PDF。
