# 12: 押金收取与余额流水

Status: open
Label: ready-for-agent
Type: task
Blocked by: 11
Spec: [平台Spec](../spec.md)
User stories: 79, 80

## What to build

合同可按实际需要约定押金类型与金额；押金实收进入押金台账与流水，可查询来源、余额与历史，并建立后续抵扣、退款与转结的额度边界。

- 合同专员或财务可为合同按需设置押金类型与金额，不强制任何无关押金类型；押金作为独立分类账单出账，复用票据 10 的合同快照与出账能力。
- 押金账单收款通过票据 11 的收款能力登记；实收在同一数据库事务内写入押金台账与流水，台账余额与流水累计一致，不重复加款。
- 可查询押金来源（合同、押金账单、收款）、当前余额与全部历史流水，凭证附件按业务归属鉴权下载。
- 台账区分余额、待退/待转保留额度与可用额度，为票据 14 的退款与票据 18 的转结提供来源和可用额度边界；本票不交付抵扣、退款或转结操作本身。
- 押金不属于租金收入，在账期核销与收入口径查询中单独分类展示。

## Acceptance criteria

- [ ] 合同可按需设置押金类型与金额并生成押金分类账单；未设置押金的合同不产生强制押金。
- [ ] 押金账单收款经 HTTP 完成后，押金台账余额与流水累计一致；同一业务号重复提交不重复加款。
- [ ] 台账可查询来源、余额与历史流水，私有凭证仅按业务归属鉴权下载。
- [ ] 待退/待转保留额度从可用额度中扣除，可用额度公式可核对；后续操作留给 14/18 接入。
- [ ] 押金在收入与账期口径中单列，不并入租金收入。
- [ ] 企业 A 账号查询企业 B 押金台账被拒绝。
- [ ] 无财务权限的运营账号无法设置押金或查看他园区押金台账。
- [ ] 台账与流水在同一事务写入，任一步失败时整体回滚，不出现只入台账或只入流水的记录。
- [ ] 未收押金账单不得触发台账入账。
- [ ] UI 可完成押金设置、余额与流水查看，DB 持久化；Flyway migration 与真实 HTTP/MySQL 验证证据齐备。

## Context

本票对应 [平台Spec](../spec.md) Implementation Decisions 第 29 条前段与 User Stories 79—80；押金的定义与收入口径见 [GLOSSARY](../../../GLOSSARY.md)，押金不属于租金收入。押金账单复用票据 10 的分类出账与条款快照，实收复用票据 11 的收款能力。

本票只建立台账、流水、余额与保留额度边界，抵扣、退款与转结分别在 14、18 交付，不提前交付未实现操作。

押金账单与收款复用票据 10、11 的账单和收款事实，不另建第二套金额来源；列表、详情与附件使用相同数据权限。台账与流水同事务依赖单库事务边界，见 [ADR 0001](../../../docs/adr/0001-modular-monolith.md)。

验证以真实 MySQL 与真实认证上下文执行 HTTP 请求，保留原始输出；未执行的验证不写为通过。
