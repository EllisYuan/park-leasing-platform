# 16: 退租结算、押金抵扣与应退抵销

Status: open
Label: ready-for-agent
Type: task
Blocked by: 14, 15
Spec: [平台Spec](../spec.md)
User stories: 81, 86, 87, 89, 90, 91, 92

## What to build

财务可完成整合同退租的可复算结算：汇总欠费、押金、赔偿与独立预收应退，批准押金抵扣与应退抵销，并将预收应退接入退款链。同时接住未签合同取消但已有实际收款的应退事项，保留资金来源与取消依据。

- 结算汇总合同欠费、押金余额、经审批的赔偿与独立的预收应退；预收租金应退与押金分列，不混为同一性质。
- 批准押金抵扣时明确目标应收账单，在同一事务内扣减押金并核销目标账单；同一账单不重复核销，押金不重复扣减。
- 欠费与应退抵销需明确关联账单与批准依据，双方金额与来源可核对。
- 票据 13 形成的预收应退，以及 08/11 保留的未签取消合同已收款应退，分别保留来源并接入票据 14 的退款链路（申请、异人复核、线下执行记录），按来源分次退款，冻结与执行防重。
- 结算与抵销是账务事实，不生成虚假现金收款或退款流水。
- OUT 已登记且合同占用解除后，即使存在待退款，单元可释放并重租；历史欠款持续可收。
- 结算中引用的原收款标记使用关系，供票据 19 校验依赖并拒绝孤立红冲。

## Acceptance criteria

- [ ] 结算接口汇总欠费、押金余额、赔偿与独立预收应退，金额与明细可复算并持久化。
- [ ] 批准抵扣指定目标账单后，同一事务内完成押金扣减与账单核销；重复批准不重复核销。
- [ ] 欠费与应退抵销有明确关联与批准记录，双方金额守恒可核对。
- [ ] 预收应退通过 14 链路申请、异人复核并记录实际线下执行，分次退款有来源且执行不重复。
- [ ] 未签合同取消但已有实际收款时，应退可追溯原款与取消依据，并经 14 链路分次退还且不超退、不重复执行；使用受控前置资金事实验证，不为构造场景放宽正常出账的审批与签署条件。
- [ ] 无来源或超过可抵金额的抵扣、抵销被拒绝。
- [ ] OUT 登记且占用解除后待退款不阻塞单元重租；历史欠费仍可继续收。
- [ ] 结算引用的收款被标记使用，19 可据此拒绝孤立红冲。
- [ ] 非财务或无权限账号执行结算被拒绝；他企业结算不可见。
- [ ] UI 可操作结算与抵扣并查看守恒明细，Flyway migration 可在空库升级，真实验证证据保存。

## Context

本票对应 [平台Spec](../spec.md) Implementation Decisions 第 30—31 条与 User Stories 81、86—87、89—92，是退租侧的资金结算闭环。结算与押金抵扣术语见 [GLOSSARY](../../../GLOSSARY.md)：结算不等于 OUT 交接，也不等于实际退款。

押金来源与可用额度来自 12/14，费用截止与 OUT 事实来自 15，账单调整应退来自 13，未签取消已收款应退由 08/11 移交；本票将两类应退接入 14 的退款链，并标记被使用的收款供 19 校验依赖。整合同与释放边界见 [ADR 0002](../../../docs/adr/0002-whole-unit-contract-boundary.md)，事务一致性见 [ADR 0001](../../../docs/adr/0001-modular-monolith.md)。
