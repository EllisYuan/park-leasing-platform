# 19: 有关联依赖保护的收款红冲

Status: open
Label: ready-for-agent
Type: task
Blocked by: 16, 18
Spec: [平台Spec](../spec.md)
User stories: 76, 77, 78

## What to build

复核人员可对错误收款发起全额红冲，经异人复核后追加反向流水；已被后续业务使用的收款拒绝孤立红冲，并展示依赖。

- 错误收款只能申请全额红冲，部分金额请求被拒绝；申请后由不同人员复核，提交人与复核人相同被拒绝。
- 复核通过后追加反向流水，原收款与复核依据完整保留。
- 原收款已被押金抵扣、押金转结、退款或结算使用时，红冲申请被拒绝并展示依赖业务；须先在关联业务中经合法审批更正或撤销依赖，之后才能重新申请。
- 红冲是纯记账更正：不生成实际退款记录，不改变实际到账与现金统计；真实退款仍由退款执行链记录。
- 并发与重复申请只产生一组反向流水。
- 红冲后账单未收余额、押金台账与流水保持守恒，核销关系可核对。
- 越权账号或他企业收款不可发起或复核红冲。

## Acceptance criteria

- [ ] 错误收款经异人复核完成全额红冲，原收款保留并新增一条反向流水，复核人持久化。
- [ ] 部分金额红冲请求被拒绝。
- [ ] 已被抵扣、转结或退款依赖的收款红冲被拒绝，响应展示依赖业务。
- [ ] 依赖经关联业务合法更正后可重新申请红冲（16/18 来源可校验）。
- [ ] 红冲不产生实际退款或现金流水，实际到账统计不变。
- [ ] 并发或重复红冲同一收款只产生一组反向流水。
- [ ] 红冲后账单未收余额、押金余额与流水合计守恒。
- [ ] 同人复核被拒绝；他企业收款红冲不可见、不可操作。
- [ ] UI 可完成申请、复核并查看关联反向记录，Flyway migration 可在空库升级，真实验证证据保存。

## Context

本票对应 [平台Spec](../spec.md) Implementation Decisions 第 28 条与 User Stories 76—78。收款红冲只做全额记账更正，与实际退款分离，术语见 [GLOSSARY](../../../GLOSSARY.md)。

依赖保护覆盖票据 16 的结算使用与票据 18 的押金转结来源；红冲记录本身依赖票据 11 的收款。提交人身份来自服务器会话（见 [ADR 0003](../../../docs/adr/0003-browser-session-authentication.md)），异人复核据此校验；并发与唯一约束依赖单库事务，见 [ADR 0001](../../../docs/adr/0001-modular-monolith.md)。

验证证据使用真实 MySQL 与真实认证上下文执行 HTTP 请求并保留原始输出，未执行的验证不写为通过。
