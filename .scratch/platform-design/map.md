## Decisions-so-far

### 第一轮

用户回复：`Q1 是； Q2 是； Q3 是`。

1. **Q1：交付目标。** 工程型毕业设计，交付可运行演示的前后端、migration、演示数据、关键业务验证和论文所需实际证据。
2. **Q2：运营模式。** 一个运营商管理多个园区、服务多家承租企业，不做多运营商入驻的 SaaS。
3. **Q3：推进方式。** 分阶段先做核心闭环，再完善门户与企业端；助手推荐技术，版本经最小集成后锁定。工期和人数尚未提供，未确认 12—16 周排期。

### 第二轮

用户回复：`Q4 确认； Q5 确认； Q6 确认`。

4. **Q4：最终功能。** 园区房源、招商跟进意向审批、合同交接续退租、租金物业账单/线下部分收款/押金、门户留资预约、企业中心、报修工单、基础统计Excel、权限公告日志。在线支付、能耗自动分摊、投资协议及政策申报为扩展；真实电子签章、税务接口、年度产值税收考核不列交付。
5. **Q5：技术方向。** Java 21、Maven、Boot（优先评估4系列受支持稳定线）、MyBatis-Plus、MySQL 8.4、Vue 3、TypeScript、Vite、Router、Pinia、Element Plus。精确版本待验证。
6. **Q6：整体架构。** 同仓库前后端分离的模块化单体；`server/`、`web/`、`deploy/`、`docs/`，一后端一数据库，业务分包、内部再分层。

### 第三轮

用户回复：`Q7—Q11 全部确认`。

7. **Q7：角色与授权。** 员工可兼任管理员/园区负责人/招商经理/专员/合同/财务/物业；角色关联指定园区，操作权限与本人/部门/园区数据范围并行。退款与红冲保留经办复核。企业账号首版单企业，同企业多账号，可查本企业跨园区授权业务。访客留资和账号绑定分别处理，执照不自动赋予合同访问权。
8. **Q8：出租粒度。** 园区→楼栋→出租单元，楼层为属性；空间不重叠、整单元出租。同一合同同企业同园区、可多单元但共同租期，单元价格/面积分别快照；跨园区分合同，增租另立合同，不支持有效合同部分退租，续租新合同关联原合同。
9. **Q9：后端结构。** 单 Maven 应用，common/security/system/asset/enterprise/investment/lease/finance/property/reporting 分包，各业务按需 controller/service/mapper/entity/dto/vo，跨业务经明确 Service 协作，计费独立验证，reporting 只读。
10. **Q10：前端结构。** 一个 Vue SPA，公开门户、`/enterprise/*`、`/admin/*` 三布局；门户企业端适配手机，运营端以 PC 为主、手机基本可访问；后端独立鉴权。
11. **Q11：配套组件。** Flyway、Spring Task及人工补跑、本地私有文件和归属鉴权、POI、兼容的springdoc-openapi、可选Redis；核心业务可独立运行。尚未完成依赖验证。

## 第四轮确认归档

用户回复：`Q12—Q16 全部确认`。以下五项均已确认，详细规则见 [核心业务规则](../../docs/design/core-business-rules.md)。

- **Q12 已确认：登录与部署。** 第一方浏览器 SPA 采用 Spring Security 服务器 Session + HttpOnly Cookie + CSRF 防护；开发 Vite 代理，部署 Nginx 同源，一后端实例，初版内存 Session，重启重新登录。闲置30分钟过期，无长期免登录，可多设备登录；账号停用和密码/授权变更撤销相关会话或重新校验。HTTPS 环境 Cookie 使用 Secure。已取代旧文档未确认的 JWT 建议，见 ADR 0003。
- **Q13 已确认：开户和企业权限。** 首版运营核验企业与联系人后创建企业管理员账号，管理员维护本企业资料并邀请受限成员；普通成员仅基本查询和报修，合同敏感资料按权限开放。访客无需账号可留资和申请看房。企业注册自助审核页延后，不接短信。全局系统管理员与园区经营授权分别处理。
- **Q14 已确认：招商报价与占房。** 一意向一单元；指导价以上业务校验通过，指导价与底价之间经理审批，低于底价经理及园区负责人审批并说明。通过后从批准时间暂占7天，记录拟租区间，仅阻止冲突区间；一单元初版最多一个有效意向暂占。驳回/撤回/过期只释放自身，合同审批原子接管；过期后重新校验和审批，不自动续锁。免租等经济条件由合同审批复核。
- **Q15 已确认：合同与交接。** 审批、签署、合同占用区间、IN/OUT及结算分别记录。日期含首尾，6月30日结束则下一租约7月1日起；占用区间含免租期，不支持签后随意改日期或提前交付。审批签署后可出首期预收账单；到约定起日且IN确认后登记实际占用；计费按合同约定，不因录入交接滞后自动改价。OUT确认现场腾空后解除实际占用，另校验合同占用区间，退款未完成不阻塞物理释放。
- **Q16 已确认：计费模型。** 单元固化面积/租金和物业单价（元/平方米/月）、含税约定价，金额BigDecimal/DECIMAL；合同付款周期1/3/6/12月；合同开始月月初作为账期锚点，首尾裁剪、自然月日历天数折算。仅期初连续免租，物业费不随租金免除；可选周年复利递增、计租日起算。明细保留算式与快照，逐明细舍入至分后汇总；出单提前天数与付款到期日规则分别记录。

认证依据：只读官方 Spring Security session-management、csrf、logout 和 Boot application-properties 文档，支持服务器会话、CSRF 与退出失效的方向，不构成当前依赖组合运行验证。来源：<https://docs.spring.io/spring-security/reference/servlet/authentication/session-management.html>、<https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html>、<https://docs.spring.io/spring-security/reference/servlet/authentication/logout.html>。

## 第五轮确认归档

用户在Q17—Q21后回复：`全部确认`。详见 [核心业务规则](../../docs/design/core-business-rules.md)。

- **Q17 已确认：账单收款。** 租金物业押金分类、合同多单元明细、定时人工幂等补漏；一收款一账单、可部分收款、金额正不超余额；实际到账日与录入时间分开、独立业务号。错误收款仅全额红冲、异人复核非实际退款；未收账单审批作废重开、有收款走调整；不自动计违约金。
- **Q18 已确认：审批续租。** 合同专员提交→财务复核→负责人终审，禁止本人提交自审，驳回保留历轮。未签可取消释放预订，已收仍留待退款。同企业同单元次日续租审批签署后承接实际占用，不假造搬离。
- **Q19 已确认：预约公海。** 匿名留资回访、不公开内部进度；未来14天09—12/14—18每30分钟一单一房，确认分配人员，房与人时段均不冲突。看房不占租赁资源、暂占可安排带看不承诺冲突租期；阶段可跳不造事件；公海手动退回分配领取转交，无自动回收。
- **Q20 已确认：工单通知。** 有权使用单元报修，派单处理完工确认/返工；完工生成通知起48小时可超时关闭，非验收、不评分、可申请返工。站内待办未读定时刷新，不接短信邮件WebSocket。
- **Q21 已确认：统计。** 实际占用计租面积/纳入出租面积（维修在内停用移出）、未来预订分开；可交付综合占用区间/暂占/维修；同批线索真实事件非伪漏斗；账期应收核销与现金到账日统计分开，押金单列不作收入。

## 第六轮确认归档

用户回复：`Q22—Q25 全部确认`。以下均已确认，详见核心规则、数据与接口草案及交付方案。

- **Q22：押金与整合同结算。** 按合同分类型确认押金金额、账单收取并同步流水；扣欠费需经批准且关联应收，原子核销、防重复；退款申请/异人复核/实际执行分别记录，仅实退减余额，待退保留额度不重复抵扣。续租押金可批准后成对内部转结，非新现金非租金。提前终止保留原合同和批准截止日，整合同处理；到期/终止及OUT均校验后释放资源，财务未结不阻塞；明细重算产生调整、预收多款列独立应退，不混入押金，赔偿人工批准。欠费与应退抵销须留凭证，退款不是红冲。
- **Q23：数据与API约定。** 按当前确认重整数据模型，保留可追溯旧设计映射、不照38表全建。统一/api、分页错误与状态、金额字符串/日期明确；历史合同及资金不硬删，幂等与锁统一；附件图片/PDF私有鉴权、单文件默认20MB；同步导出默认1万行超出缩范围；数据文件备份及恢复验证。
- **Q24：界面方向。** 运营端清晰紧凑表单台账工作台，门户偏园区介绍房源展示，企业端强调待办合同账单；浅色中性背景加深蓝重点，移动适配沿用Q10，基础图表，不做3D场景或数字孪生。
- **Q25：阶段与验证。** 第一可运行链路登录园区授权/房源企业/招商意向/审批签约/IN/分段首期账单/线下部分收款/企业只读，随后补全退租押金等财务、门户预约工单统计、部署证据。先验证最小依赖锁版；开发Maven+Node+MySQL，部署Nginx+jar单实例，可选Compose；本轮不实现在线支付/能耗政策扩展，标展望。按金额日期/并发归属/幂等与恢复等真实验收，不预填性能数字。

上述确认来自第六轮，不与第五轮混淆。最终数据/API名称和DDL尚未运行落地；用户仅确认设计，不表示授权开始代码实现。
